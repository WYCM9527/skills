## 局部规范候选

- `scope-map.json` 是唯一机器登记册；只有确认了边界、父级、理由与权威来源后才登记 Scope。
- 单页或专区的不同视觉不能仅凭一个颜色或尺寸差异建立 Scope；Theme、组件例外和 Drift 另行记录。
- 独立品牌、入口／发布和组件契约证据同时存在时，记录为独立设计系统候选，并暂停等待用户确认。

## Theme 候选

- 记录已有 Theme 的模式、默认模式、根级选择器、运行时切换线索和权威来源；没有证据时不凭空创建 Theme。
- `theme-map.json` 是确认 Theme 后唯一的机器登记册。Core 代表默认 Theme，`themes/<id>/` 只记录相对 Core 的 delta。
- Scope 与 Theme 不自动组合；若同一 Semantic 在两者中都需要覆写，记录为待用户确认的交互，而不是猜测性 CSS。

## 后续治理

- 日常文案、数据或图片内容更新不改变设计系统。
- 新增、跨页面复用或修订视觉决定时，先记录提案和用户选择；一次性差异先标为 Drift 或试验。
