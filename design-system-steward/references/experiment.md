# Experiment：中文 Prompt 与可回滚试验

V1 的 experiment 不改生产页面。它的目标是让团队在明确边界下试用已确认的设计语言，再决定是否单独发起代码迁移任务。

## 推荐 Prompt 骨架

```text
请只在 [试验页面或新分支] 验证 design-system/ 的设计语言，不修改现有生产组件。

必须：
1. 阅读 design-system/DESIGN.md；
2. 只使用 design-system/tokens/ 中已定义的 token；
3. 不新增未命名的色值、间距、圆角、阴影或字体尺寸；
4. 报告每个使用到的 Semantic token 与它表达的意图；
5. 如果现有 token 不能表达需求，停止并提出 token 提案，不要临时硬编码。

任务：[填写一个小范围组件或页面试验]
```

## 验收清单

- 试验范围是否只有预先指定的组件或临时页面？
- 是否没有直接写入 `dist/tokens.css`？
- 是否没有新增未经确认的视觉数值？
- Semantic token 名称是否表达用途，而不是颜色或像素？
- 如果出现组件例外，是否提出了 Component token 提案而不是复制值？
- 视觉是否满足 `DESIGN.md` 的 Do/Don't、对比度和响应式规则？

## 回滚

试验必须放在独立分支、独立 demo 或可单独删除的提交中。验收失败时，只回滚试验代码；不要回滚已确认的 token 真相源，除非用户重新确认设计决策本身。
