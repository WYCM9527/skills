# AI 教程写作模式

仅在主题涉及 AI 模型、工具、提示词、Agent 或生成式工作流时使用本文件。按任务选取相关部分，不机械加入全部章节。

## 先确定 AI 任务类型

- **产品操作**：重点说明入口、模型或模式选择、输入要求、操作步骤和结果验证。
- **提示词与工作流**：重点说明任务拆解、上下文、约束、输出格式、迭代和复用。
- **API 或集成**：重点说明权限、最小调用、参数、响应、错误处理、费用与数据边界。
- **评估或比较**：先定义评价标准和测试材料，再比较结果；不以单个演示替代结论。
- **生成式媒体**：说明素材要求、提示结构、参数、候选筛选、后期处理和版权或隐私风险。

## 写出可用的提示词

提供一份能直接复制的完整提示词，而不是若干互不相连的“关键词”。按需要包含：

1. 任务和目标结果；
2. 必要背景与输入材料；
3. 明确约束与禁止事项；
4. 输出结构或验收标准；
5. 只有确实能减少歧义时才加入示例。

在代码块后解释每个需要替换的变量。不要把语气词或“你是世界级专家”描述成决定效果的魔法；解释真正影响结果的上下文、约束和评价标准。

## 展示结果与判断标准

不要只展示“看起来不错”的样例。说明读者如何判断结果是否可用：

- 是否完成了明确任务；
- 是否忠于输入事实；
- 是否满足格式、长度和风格约束；
- 是否存在遗漏、幻觉、敏感信息或不可执行内容；
- 是否需要人工复核，以及复核什么。

示例输出只保留足以说明结构和质量的部分。若结果不可稳定复现，明确说明波动来源。

## 给出迭代路径

使用一个短循环代替堆叠“万能提示词”：

1. 用最小可行输入生成第一版。
2. 根据验收标准指出具体差距。
3. 一次只修改高影响变量，例如上下文、约束、示例或输出格式。
4. 保留有效部分并再次评估。

将常见失败写成“现象 → 可能原因 → 修正动作”：

- **回答空泛** → 缺少具体背景或验收标准 → 补充真实输入和期望结构。
- **事实错误** → 要求模型凭记忆回答时效性事实 → 提供来源并要求引用或先检索。
- **格式漂移** → 输出约束含糊或相互冲突 → 给出单一、明确的格式规范。
- **内容过长** → 没有优先级和停止条件 → 指定必须保留的信息与删减规则。
- **结果不稳定** → 任务过大或一次承担多个目标 → 拆成可验证的小步骤。

## 连接真实工作

至少给出一个完整工作场景，说明：

- 输入从哪里来；
- AI 负责哪一步；
- 人在哪些节点判断或批准；
- 输出进入哪个后续流程；
- 如何保存可复用的提示词、模板或评价标准。

不要把“让 AI 自动完成全部工作”当作默认最佳实践。根据错误成本安排人工复核。

## 只在相关时补充边界

- 对模型名称、功能、上下文限制、价格和配额使用当前官方来源核实。
- 涉及敏感资料时，说明脱敏、权限、数据保留或企业策略要求。
- 涉及代码、医疗、法律、金融或其他高风险决策时，明确必要的测试与专业复核。
- 涉及生成内容发布时，提醒检查版权、肖像、品牌和平台政策。
- 不要把成本、安全和版本说明复制到所有 AI 教程；它们必须与当前任务直接相关。

## AI 教程交付检查

- [ ] 提示词或配置可以直接复制，变量含义明确。
- [ ] 读者知道预期输出长什么样，以及如何评价。
- [ ] 至少说明一个高概率失败和修正方式。
- [ ] 示例对应真实工作链路，而不是孤立演示。
- [ ] 时效性能力与限制已核实，没有凭印象填写模型信息。
- [ ] 人工复核、隐私、费用和风险只在相关时出现。
